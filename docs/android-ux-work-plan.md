# Android 위젯 개선 업무계획서

작성일: 2026-11-01 (KST) · 구현: 새 Codex 세션, **Luna (`gpt-6-luna`), 추론 강도 max**

## 1. 승인 범위와 현재 상태

사용자는 초안 APK를 실제 사용했고 크기에 따른 레이아웃 전환을 확인했다. 색상·글씨 크기·투명도 설정, 탭 반응 개선을 요청했으며, [UI/UX 검토서](android-ui-ux-review.md)의 11개 개선점까지 모두 구현하도록 승인했다. 이 문서는 그 전체 범위의 실행 설계다. 별도 계획 승인을 다시 받지 않고 새 구현 세션에서 작업한다.

기존 Kotlin/Glance 앱을 개선한다. 새 앱을 만들거나 웹앱을 WebView로 합치는 작업이 아니다. 웹앱·위젯은 같은 GitHub 파일을 공유하고, 공유 형식과 unknown 필드 보존·sha 충돌 재시도 규칙은 유지한다. 꾸미기·실행 취소·화면 상태는 Android 로컬 저장으로 구현한다. 외부 서비스, 서버, Firebase는 추가하지 않는다.

기존 기록은 51개 단위 테스트와 `gradlew.bat test assembleDebug` 성공이다. 이는 개선판의 검증을 대신하지 않는다. 최근 ADB 조회에 연결된 기기는 없었고 기존 AVD는 Pixel_6a였다. S25의 세 크기·다크 모드 전체 확인과 상호 반영은 여전히 미완료다. 초안 사용 경험만으로 개선판 수동 검증까지 완료 처리하지 않는다.

읽기 우선순위: 사용자 지시 → `docs/data-format.md` → 이 문서와 [03 수행지시문](instructions/03-android-widget-ux-luna.md) → 검토서 → 초기 02 문서. 초기 문서의 '앱이 아직 없다'는 과거 기록이다. 기존 코드와 설치 데이터 위에서 작업한다. 표시량·설정 화면·체크 행 유지에 관한 이번 설계는 초기 지시문을 보완한다.

## 3. 로컬 상태와 빠른 반응

### 관찰 가능한 한 방향 상태 흐름

- `DashboardStore`에 캐시·보류 작업·동기화 상태의 관찰 Flow를 추가한다. 한 preferences 스냅샷에서 표시 모델을 만들고, 재조합마다 `first()`로 여러 번 읽어 섞인 상태를 만들지 않는다.
- `provideGlance`에서 초기 데이터를 읽은 뒤 **`provideContent` 안에서 Flow를 collectAsState로 구독**한다. 현재처럼 로컬 snapshot을 고정 캡처하지 않는다. 외부 저장 변경 뒤 `updateAll`도 호출하여 비활성 세션을 깨운다.
- 표시 Flow의 변환은 순수해야 한다. Flow 수집/재조합에서 GET·PUT·설정 쓰기·Worker 재등록을 하지 않는다. 렌더링마다 토큰을 복호화하지 않고 연결 변경 시 확인한 상태/Worker 결과를 사용한다. 토큰 평문은 UI 상태에 노출하지 않는다.
- 체크 접수는 로컬 원자적 작업 저장 → 관련 행·진행률·저장 중 상태 반영 → 지속 가능한 Worker 등록 순서다. 네트워크와 공용 동기화 Mutex를 기다리기 전에 로컬 상태가 갱신되어야 한다. Worker 등록 실패는 해당 overlay만 제거한다.
- 같은 todo의 중복 탭은 차단하고 서로 다른 todo는 각각 표시한다. 여러 위젯에서 같은 todo를 조작해도 작업 id·연결 세대로 식별한다. 다른 항목 전체를 과거 snapshot으로 되돌리지 않는다.
- 네트워크 호출은 기존 4회 PUT 상한, 원본 필드 보존, 요청 제한 시간을 유지한다. 앱 범위 OkHttpClient 재사용을 검토한다. WorkManager를 없애거나 `GlobalScope`로 저장을 흘려보내는 방식으로 속도를 맞추지 않는다.

### 실행 취소

- 보류 완료 행은 목록에서 제거하지 않고 체크 상태와 `저장 중`으로 유지한다. 성공 후에는 가장 최근 완료 1개의 제목과 **실행 취소**를 보여준다. 보류 중 같은 작업의 취소는 받지 않으며, 실패 시 원래 행으로 복구한다.
- 최근 완료 기록은 성공한 작업 id, todo id, 성공 직전 서버의 원래 doneOn, 저장한 목표값, 현지 날짜, 연결 세대와 함께 로컬에 저장한다. nullable/예전 날짜인 원래 doneOn을 임의로 오늘/반전값으로 바꾸지 않는다.
- 실행 취소도 새로운 목표값 작업이다. 최신 GET의 해당 doneOn이 방금 저장한 목표값과 일치하는지 확인한 뒤 이전 값으로 돌린다. 다른 기기에서 값이 달라졌거나 항목이 삭제됐으면 덮어쓰지 않고 재확인 안내를 보여준다. 충돌 재시도마다 조건을 재검사한다.
- 취소 성공·날짜 변경·연결 변경·더 최신 완료 기록 생성 시 이전 undo 액션은 무효화한다. 오래된 PendingIntent는 operation id/연결 세대/현지 날짜 검사로 거부한다. 보류 작업은 프로세스 종료 후 복구한다.
- '최근 완료 1개' 외의 이전 완료 항목은 전체 보기에서 접근한다. 위젯 안의 일반 앱 Snackbar 사용을 전제하지 않는다.

## 4. 꾸미기 설정과 미리보기

### 저장 범위

- `WidgetAppearance`를 DataStore의 별도 키로 저장한다. 신규 위젯용 기본값과 `appWidgetId`별 설정을 분리하고, id를 검증한 `위젯 설정` 진입점에서 편집한다. 삭제된 위젯 키는 정리한다.
- 기존 설치에는 자동 테마·100% 글씨·불투명 배경을 기본으로 적용한다. 꾸미기 저장/미리보기/초기화는 기존 토큰·연결 세대·원격 캐시·보류 작업을 초기화하지 않는다.
- 앱에서 '기본 설정'과 개별 위젯을 선택하게 한다. '이 위젯에 적용'과 '모든 위젯에 적용'은 별도 명시적 액션이다. 생성된 위젯에 다른 위젯의 설정을 암묵적으로 덮어쓰지 않는다.

### 조절 UI

- 색상: 자동/프리셋/사용자 지정. 사용자 지정은 배경·강조색의 `#RRGGBB`를 검증하고 색상 견본을 제공한다. 글자색은 배경에 맞춰 자동 대비를 기본으로 하며, 다크 모드 선택도 미리 볼 수 있어야 한다.
- 글씨: 80~150%, 10% 단위. 모든 주요 typography에 일관되게 적용하되 시스템 접근성 배율을 제거/고정하지 않는다. 값은 슬라이더뿐 아니라 현재 퍼센트·접근성 조절로 읽을 수 있게 한다.
- 투명도: UI에서 '배경 불투명도'라고 명확히 표시한다(0%=완전 투명, 100%=불투명). root 전체 alpha를 낮추지 않는다. 배경만 투명하게 하고 글자·아이콘·체크·진행률은 유지한다.
- 완전 투명 배경은 임의의 배경화면에서 대비를 보장할 수 없다. 밝음/어두움 예시 배경을 미리 보고 선택할 수 있게 하며 텍스트 주변 대비 보조 배경을 옵션으로 제공한다. 배경화면을 읽거나 관련 권한을 추가할 필요는 없다.
- 미리보기는 변경 즉시 반영하되 실제 위젯 적용은 `적용` 버튼에서 한다. `취소`는 저장 전 draft를 버리고, `기본값 복원`은 자동 테마/100%/100%로 draft를 되돌린다. 실제 개인 정보 대신 예시 데이터임을 표시한 미리보기도 지원한다.
- Compose 미리보기와 Glance에서 색상·배율·표시 모델을 공유한다. Compose 근사 미리보기를 실제 Glance 렌더링 검증으로 간주하지 않는다.

## 5. 레이아웃·탐색·접근성

- `SizeMode.Responsive`를 유지하되 가용 dp와 글꼴 배율에 맞는 bucket/표시 계획을 구체화한다. 단순히 폰트·아이콘을 비례 축소하지 않는다. 실제 지원 Glance API로 `WidgetPresentation` 같은 순수 표시 모델을 구성해 테스트할 수 있게 한다.
- 작은 크기는 오늘 진행·다음 시간 일정·active 수를 기본 요약으로 한다. 큰 글꼴/오류로 공간이 부족하면 보조 정보를 줄이고 '전체 보기/확대 안내'로 원문 접근을 보장한다. 200% 글꼴에서 모든 정보를 억지로 넣지 않는다.
- 중간은 요약·다음 시간 일정과 스크롤 가능한 할 일/상세 영역을 배치한다. 큰 크기는 할 일·일정·프로젝트를 스크롤 가능한 구획으로 제공한다. 원래 한도인 할 일 3개/오늘 일정 5개/active 4개는 기본 상세 제공량의 상한으로 유지하고, 실제 가시량과 숨겨진 수를 명시한다. 목록이 늘거나 글꼴이 커지면 스크롤/더보기로 접근한다.
- 모든 크기에서 다음 시간 일정 1개를 종일 목록과 별도로 우선 제공한다. 중간의 종일 항목이 다음 회의를 밀어내지 않게 한다. 상세 일정의 종일 우선·시작 시각 정렬은 유지한다.
- Header·undo·새로고침·체크·더보기 등 각 액션의 터치 영역은 48×48dp 이상을 목표/검증 기준으로 한다. 공간이 부족하면 별도 행 또는 관리 화면으로 보낸다. 작은 헤더에 세 개 버튼을 무리하게 넣지 않는다. 작은 위젯은 웹앱 여는 제목과 새로고침을 우선하고 설정은 런처 재구성/앱의 위젯 목록에서 접근 가능하게 한다. 중간/큰 크기는 명시적 설정 액션도 제공한다.
- 제목과 빈 바탕의 웹앱 열기는 유지하되 체크 행 및 주변 터치 영역과 분리한다. 데이터 id와 widget id를 구분하고 임의 웹 경로를 만들지 않는다. 전체 보기는 저장된 검증된 웹 URL을 연다. 실제 있는 앵커만 사용한다.
- 긴 할 일 제목은 가용 공간에서 두 줄까지 허용하고, 프로젝트 다음 과제는 진행률 숫자보다 충분한 공간을 준다. 끝까지 표시하지 못하면 전체 보기 경로와 개수를 남긴다.
- 문자 `■□` 진행 막대는 Glance 진행 컴포넌트로 바꾸고 완료 개수/전체 수와 백분율 의미를 제공한다. `↻/☑/…` 기호만으로 의미를 전달하지 않는다. 선택 상태·제목·수행 동작·저장 중을 읽을 수 있게 한다.
- 빈 상태는 데이터 없음/모두 완료/active 없음/연결 전/캐시 없는 실패/이전 데이터 사용을 구분한다. 원격 형식 오류를 빈 목록이나 '전부 완료'로 표현하지 않는다.

## 6. 동기화 신뢰성과 일정 경계 갱신

- 파일별 상태에 성공 시각, 마지막 시도 결과, 파일 부재(404)와 오류를 구분한다. todos/projects/calendar를 막연히 같은 성공 시각으로 표시하지 않는다. 404 상태도 저장해서 예전 calendar 캐시가 다음 렌더에서 연결된 것처럼 되살아나지 않게 한다. 원격 GitHub 형식은 변경하지 않는다.
- 전체 갱신 완료는 필요한 읽기가 성공/정상 부재로 끝난 실행에 대해서만 기록한다. 한 파일 성공을 전체 성공으로 승격시키지 않는다. calendar 미연결은 오류 대신 숨김으로 처리한다. 원격 데이터 생성 시각과 기기의 '읽기 확인 시각'을 혼동하지 않는다.
- 위젯에는 `동기화 중`, `방금 확인`, `어제 09:00 · 이전 내용`, `할 일 갱신 실패` 등 짧은 요약과 재시도/설정 액션을 제공한다. 관리 화면에는 파일별 상세를 제공한다. 인증/파싱/오프라인 실패를 구분하고 오류 전체를 한 줄에 억지로 넣지 않는다.
- `CalendarBoundaryRules`에서 다음 오늘 일정 시작/종료 또는 다음 현지 자정을 계산한다. 네트워크 제약 없는 고유 OneTimeWork가 캐시만으로 현재 시각의 화면을 재계산하고 다음 경계를 예약한다. 같은 경계의 즉시 재등록 루프·중복 작업이 없어야 한다.
- 원격 갱신 완료, 일정 캐시 변경, 날짜/시각/시간대/부팅 변경, 위젯 추가/삭제에서 예약을 복구/정리한다. 기존 자정 작업과 경계 작업은 역할을 통합하거나 상호 중복을 피하도록 관리한다.
- 30분 원격 동기화는 유지한다. 정확한 분/자정 실행은 Android 절전 정책상 보장하지 않으며 exact alarm 권한을 추가하지 않는다. 수동 새로고침·앱 재진입·실행 가능한 다음 로컬 갱신에서는 반드시 현재 시각을 반영한다.

## 7. 앱 관리 화면과 설치 데이터 유지

- 앱 기본 화면: 연결 요약·최근 상태, 위젯 목록, 꾸미기, `위젯 추가`, `웹앱 열기`, 도움말. 미연결이면 먼저 연결 화면을 제공한다.
- owner/repo/branch/token/web URL은 `연결 변경`에 모으고 배터리 설정·토큰 발급/권한 안내는 도움말의 보조 액션으로 둔다. 저장된 토큰을 평문으로 복원하지 않는다. 읽기 연결 확인을 쓰기 권한 검증으로 설명하지 않는다.
- 지원 런처는 `requestPinGlanceAppWidget` 또는 실제 지원 pin API를 사용한다. 거절/미지원이면 수동 추가 안내로 돌아간다. API 26 호환을 유지한다. picker preview는 실제 3크기 예시를 반영하고 앱 아이콘만 쓰지 않는다. 이미지가 필요하면 코드/XML/실제 렌더에서 생성하며 라이브러리·미리보기를 위해 불필요한 모델 이미지 생성을 도입하지 않는다.
- 실제 AndroidX ViewModel과 viewModelScope를 사용한다. 비밀 아닌 draft·선택 위젯·선택 화면은 회전/재생성에 맞게 보존한다. 토큰 평문을 SavedState·파일에 저장하지 않으며, 필요 시 다시 입력하라는 명확한 안내를 준다. CancellationException은 오류로 삼켜 잘못된 실패 메시지를 만들지 않는다.
- targetSdk 36에 맞춰 edge-to-edge, safe drawing/cutout/systemBars/IME inset과 현재 테마의 시스템 바 대비를 처리한다. 뒤로가기·미저장 꾸미기 취소·키보드 다음/완료 동작을 제공한다.
- applicationId, Keystore alias, 암호화 데이터 키, 기존 캐시를 유지한다. 기존 설치 위 업데이트가 가능하도록 versionCode를 올리고 기존 debug 서명을 사용한다. 업데이트 과정에서 uninstall/clear-data를 안내하거나 실행하지 않는다. 서명 불일치가 있으면 데이터 손실 없는 해결부터 검토하고 제한을 보고한다.

### 렌더링·속도 검증

- 기존 Pixel_6a AVD 또는 사용 가능한 에뮬레이터에서 익명 예시 데이터와 가짜 repository로 검증한다. 실제 개인 GitHub 토큰 없이 렌더링 가능한 debug 전용 경로/테스트 harness를 사용하고 release 코드에 테스트 endpoint나 인증 우회를 넣지 않는다.
- 3크기·다크/밝음·긴 한글/이모지·오류·최대 데이터의 실제 화면을 저장한다. 큰 시스템 글꼴은 100/130/150/200%를 테스트하고 보완이 필요한 기기 조합을 기록한다. 선택 UI의 80/100/150%도 대표 조합으로 확인한다. 모든 조합의 무의미한 전수 반복은 피하되 극단 조합은 포함한다.
- 최소 터치 bounds·스크린리더 의미는 UI/instrumentation 또는 실제 기기 도구로 확인한다. 순수 표시 모델 JUnit만으로 실제 48dp·TalkBack·화면 잘림을 통과 처리하지 않는다.
- 속도는 '화면 반영'과 'GitHub 저장 완료'를 나눠 측정한다. 활성 세션 10회 기준 탭→pending/체크 화면 반영의 중앙값과 최댓값을 기록한다. 목표는 일반 에뮬레이터/실기기 활성 세션에서 대체로 300ms 안팎, 1초 초과 반복 없음이며 **보장값이 아니다**. 초기 프로세스 시작은 별도 측정한다. 토큰/개인 제목을 로그에 남기지 않는다.
- 가짜 서버 응답을 3~5초 지연해도 그 전에 로컬 표시가 바뀌어야 한다. 실제 Glance 활성 세션 안에서 반복 체크/새로고침/꾸미기 반영을 확인해야 정적 snapshot 버그 수정으로 판정한다.
- 자동 검증은 흐름/규칙/충돌/복구에 필요한 테스트를 추가하고 기존 51개를 퇴행시키지 않는다. 외형 상수만 복제하는 테스트로 채우지 않는다.

### 사용자 S25 확인

1. 기존 앱을 지우지 않고 개선 APK를 업데이트하고 토큰/기존 위젯이 유지되는지 확인.
2. 3크기·밝음/다크, 두 위젯의 다른 설정, 투명 배경·큰 글씨·리사이즈 확인.
3. 체크→저장 중→성공/실행 취소, 잘못 누른 경우, 새로고침/설정/웹앱 이동을 확인.
4. 위젯 체크↔웹앱 반영, 비행기 모드의 표시/실패 원복, 파일 일부 실패 안내 확인.
5. 일정 시작/종료·다음 날·절전 후 복귀에서 시각 표시를 확인. Android 제한과 실제 실패를 구분해 기록.

## 9. 결과물과 완료 판정

- 실제 수정된 Android 코드와 의미 있는 자동/렌더 검증.
- 개선 APK: 기본 `android/app/build/outputs/apk/debug/app-debug.apk` 및 식별 가능한 복사본 `android/app/build/outputs/apk/debug/Dashboard-ux-debug.apk`. 빌드 산출물은 커밋하지 않는다. 실제 생성 경로·versionName/versionCode·SHA-256을 기록한다.
- `docs/android-ux-verification.md`: U1~U4/R1~R11 각각 구현 파일·자동 근거·렌더 근거·수동 미확인 여부, 명령 결과, 측정값, screenshot 경로, APK 정보.
- `docs/android-setup.md`를 업데이트 설치·꾸미기·취소·위젯 추가·장애 복구에 맞게 보완하고 기존 검증 기록은 과거 사실로 유지한다.
- `PLAN.md`의 이번 8개 항목을 실제 결과대로 체크한다. S25 사용자 항목은 사용자 확인 없이는 체크하지 않는다. 에뮬레이터조차 사용할 수 없으면 UI 검증 미수행을 명시하고 G를 무조건 완료하지 않는다. 나머지 구현은 끝까지 진행한다.
- `docs/work-plan.md`와 대시보드에 자동 검증·렌더 검증·사용자 확인 상태를 구분해 기록한다. 초기 계획과 다른 기술 조정은 근거를 남기되 승인된 기능을 임의로 후순위 문서만 남겨 빼지 않는다.

스킬·공식 확인 자료는 [검토서](android-ui-ux-review.md)의 링크를 이어 사용한다. 현재 제공되지 않는 API는 공식 문서로 확인 후 동등한 안정 API로 구현한다.
