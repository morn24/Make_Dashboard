# Dashboard Android 위젯 설치·확인 안내

이 안내는 Android Studio로 직접 빌드하거나 debug APK를 Android 폰에 설치해 설정하는 방법입니다. 스크롤·색상 개선판은 `com.morn24.dashboard` 앱 1.5 (`versionCode 6`)이며, GitHub 비공개 저장소의 `todos.json`, `projects.json`, `calendar.json`을 읽고 할 일 체크만 `todos.json`에 저장합니다. [기존 개선판 검증](android-ux-verification.md), [레이아웃·색상 검증](android-layout-colors-verification.md), [스크롤·색상 검증](android-scroll-colors-verification.md)을 구분해 참고하세요.

## 1. 설치

### Android Studio에서 빌드·실행

1. Android Studio를 설치하고 이 저장소의 `android/` 폴더를 엽니다.
2. Gradle Sync가 끝나면 폰에서 **설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호**를 7회 탭해 개발자 옵션을 켭니다.
3. **설정 → 개발자 옵션 → USB 디버깅**을 켜고 USB로 PC에 연결합니다. 폰에 뜨는 디버깅 허용 창에서 이 PC를 허용합니다.
4. Android Studio 상단 기기 선택에서 연결된 디버깅용 Android 폰을 고른 뒤 **Run ▶**을 누릅니다. 이번 레이아웃·색상 검증은 연결된 Galaxy S20에서 했으며, Galaxy S25 확인은 별도 사용자 항목으로 남아 있습니다.

### 빌드된 APK 설치

**Google Drive로 받기 (권장, 선 없이)**: PC에서 `assembleDebug` 후 저장소 루트에서 `powershell -ExecutionPolicy Bypass -File scripts/publish_apk_drive.ps1`을 실행하면 APK가 `G:\내 드라이브\Dashboard-APK\`에 `Dashboard-<버전>.apk`와 `Dashboard-latest.apk`로 복사되고, 버전·SHA-256이 `Dashboard-latest.txt`에 적힙니다. 다른 폴더를 쓰려면 `-DriveDir` 인자나 `DASHBOARD_APK_DRIVE_DIR` 환경 변수를 줍니다. 폰의 Drive 앱에서 `Dashboard-APK/Dashboard-latest.apk`를 열어 **업데이트**를 누르면 덮어 설치됩니다. 처음 한 번은 Drive(또는 내 파일) 앱에 '이 출처 허용'을 켜야 합니다. PC에서 빌드한 파일을 그대로 옮기므로 서명이 같아 설정·위젯 모양이 유지됩니다.

스크롤·색상 개선판 debug APK는 [`android/app/build/outputs/apk/debug/Dashboard-scroll-colors-debug.apk`](../android/app/build/outputs/apk/debug/Dashboard-scroll-colors-debug.apk)입니다. `app-debug.apk`와 내용이 같은 복사본입니다. USB·클라우드 드라이브 등으로 폰에 옮겨 파일 앱에서 열거나, USB 디버깅이 허용된 기기에서 `adb install -r Dashboard-scroll-colors-debug.apk`로 설치합니다. 기존 앱을 업데이트할 때는 앱을 삭제하거나 데이터를 지우지 마세요. 같은 앱 서명 키의 APK를 덮어 설치하면 연결 설정·암호화 토큰·캐시·위젯별 모양을 유지합니다. 폰에서 출처를 알 수 없는 앱 설치를 요청하면 APK를 연 파일 앱에 한해 설치를 허용한 뒤 설치 후 다시 끌 수 있습니다. 이 파일은 debug 빌드입니다. APK를 다시 빌드하려면 프로젝트 루트의 `android/`에서 Windows는 `gradlew.bat assembleDebug`, macOS/Linux는 `./gradlew assembleDebug`를 실행합니다.

## 2. GitHub 연결

1. 앱 아이콘 **Dashboard**를 열고 저장소 소유자 `morn24`, 저장소 `dashboard-data`, 브랜치 `main`이 입력되어 있는지 확인합니다.
2. GitHub fine-grained personal access token을 발급합니다. 저장소 접근은 `dashboard-data` 하나로 제한하고, **Contents 읽기·쓰기** 권한을 줍니다. 토큰은 채팅이나 문서에 붙여 넣지 말고 폰의 마스킹된 입력란에만 입력합니다.
3. **연결 확인 후 저장**을 누릅니다. 성공 안내가 나오면 토큰은 Android Keystore의 AES-GCM 키로 암호화되어 이 기기에 저장됩니다.
4. 복원·재설치·기기 변경 뒤 저장된 토큰을 복호화하지 못하면 앱에서 새 토큰을 입력하고 다시 연결해야 합니다. 앱 백업에는 설정·토큰 암호문을 포함하지 않습니다.
5. 앱에 **배터리 최적화 설정 열기**가 있습니다. Galaxy의 배터리/백그라운드 사용 설정에서 Dashboard를 제한 대상에서 제외하면 갱신이 더 원활할 수 있습니다. One UI 버전에 따라 메뉴 이름은 다를 수 있습니다.

## 3. 홈 화면 위젯 추가

1. 홈 화면 빈 곳을 길게 누르고 **위젯 → Dashboard**를 선택합니다.
2. 작은 위젯을 끌어 놓고, 중간·큰 크기도 각각 추가하거나 모서리를 끌어 크기를 바꿉니다.
3. 작은 2×2 크기는 요약과 빠른 체크 한 건을 보여 줍니다. 공간이 있는 위젯은 오늘 할 일 전체, 오늘 일정 전체, 진행 중 프로젝트 전체를 각 영역의 목록으로 전달합니다. 4×4 큰 크기는 할 일·일정이 왼쪽 열에, 프로젝트가 오른쪽 열에 놓이고, 각 목록 안에서 세로로 스와이프해 따로 이동합니다. 좁고 긴 크기는 세 영역을 세로로 배치하며 패널별 목록을 스크롤합니다. 헤더의 전체 보기 버튼은 명시적으로 선택했을 때만 웹앱을 엽니다. 글씨 크기와 런처 셀 크기에 따라 첫 화면의 가시 항목 수는 달라집니다.
4. 홈 화면 테마를 밝게·어둡게 바꾸고 한글·긴 제목·이모지가 잘리는지 확인합니다. 런처의 셀과 글자 크기에 따라 실제 위젯 dp 크기와 줄임은 달라질 수 있습니다.

## 3-1. 위젯별 꾸미기와 빠른 체크

앱의 **꾸미기** 또는 위젯 오른쪽 위 **설정**을 누르면 해당 위젯 ID의 설정을 엽니다. 자동·밝음·어두움·바다·숲 테마 또는 사용자 색상, 글씨 80~150%, 배경 불투명도 0~100%, 대비 보조를 미리 보고 조절할 수 있습니다. 슬라이더는 초안 미리보기에만 반영되며 **이 위젯에 적용**을 눌러야 저장됩니다. 취소하면 원래 설정을 유지하고, 기본값 복원과 모든 위젯 적용도 선택할 수 있습니다. 새 위젯 기본 모양은 홈 화면의 **새 위젯 기본 모양**에서 설정합니다.

할 일을 체크하면 위젯에 먼저 반영되고 저장 중에는 행이 비활성화됩니다. 최근 완료 한 건은 위젯의 **실행 취소**로 되돌릴 수 있습니다. 동기화가 실패하면 마지막 캐시와 오류 상태를 함께 표시합니다. 자세한 파일별 상태와 다시 연결·복구 동작은 앱 홈의 **동기화 상태**에서 확인합니다.

## 3-2. 위젯에서 할 일 추가·수정, 일정·PMR 열기 (v1.6)

- **할 일 추가**: 할 일 패널 머리의 **＋**를 누르면 작은 창이 뜹니다. "내일 오후 3시 병원"처럼 쓰면 날짜·시간을 읽어 미리 보여 주고, 반복(한 번·매일·평일·주말·요일 선택)을 고를 수 있습니다. 저장하면 창이 닫히고 위젯이 바로 바뀝니다. 저장에 실패하면 창을 닫지 않고 입력을 그대로 둔 채 **다시 시도**를 보여 줍니다.
- **할 일 수정·미루기·삭제**: 할 일 **제목**을 누르면 같은 창이 수정 모드로 열립니다(앞의 체크 칸을 누르면 지금처럼 체크). 이름·반복·날짜·시간을 고치고, **내일로 미루기**, **삭제**를 할 수 있습니다. 삭제하면 위젯의 실행 취소 줄에 **삭제됨 · 되돌리기**가 나타나고, 누르면 원래 자리에 다시 들어갑니다.
- **표시**: 시간이 있는 할 일은 제목 앞에 `15:00`, 요일·매일 반복을 2번 이상 연속 했으면 `🔥n`, 날짜가 지난 한 번 할 일은 `n일 지남`이 제목 아래 줄에 보입니다(2×2는 시간·제목만). 날짜가 아직 안 된 할 일은 목록에서 빠지고 패널 머리에 `예정 n`으로 보입니다. 쉬는 요일의 요일 반복 할 일은 보이지 않습니다.
- **오늘 일정**: 일정 패널 머리를 누르면 캘린더 앱의 오늘 화면이 열립니다(앱이 없으면 웹 캘린더).
- **PMR-Wiki**: 결정 대기가 있으면 `PMR 결정 n`, 실패한 작업이 있으면 `PMR 실패 n`, PC 동기화가 하루 넘게 없으면 `PMR 끊김` 칩이 머리 줄에 나타납니다. 누르면 웹앱의 PMR 탭이 열립니다. PMR-Wiki를 안 쓰거나 문제가 없으면 아무것도 보이지 않습니다.
- **프로젝트 다음 과제 확인**(4×4): 프로젝트의 `다음 · …` 줄을 누르면 그 프로젝트의 다음 과제 목록이 동그라미와 함께 열립니다. 동그라미를 누르면 웹앱과 같이 "확인 완료"로 기록됩니다(다음 과제 목록 자체는 바뀌지 않습니다).

## 4. 서로 반영되는지 확인

1. 위젯에서 미완료 할 일을 탭합니다. 완료 표시가 먼저 바뀐 뒤 백그라운드 저장이 진행됩니다.
2. 웹앱 [Make Dashboard](https://morn24.github.io/Make_Dashboard/)를 열어 같은 항목의 완료 상태가 반영됐는지 확인합니다.
3. 웹앱에서 테스트용 할 일을 추가하거나 완료 상태를 바꾸고, 위젯의 **↻**를 눌러 새로 읽은 결과가 보이는지 확인합니다.
4. 충돌·권한·네트워크 실패 시 체크 표시는 원래 상태로 돌아오고 위젯에 짧은 한국어 안내가 보여야 합니다. 체크는 "오늘 완료/완료 취소" 의도를 저장 직전의 최신 파일에 웹앱과 같은 규칙으로 적용하므로(반복 할 일은 연속 기록도 함께 갱신), 같은 작업이 재시도되어도 완료 상태가 뒤집히지 않습니다.

## 5. 오프라인·자정 동작 확인

1. 온라인으로 위젯을 한 번 갱신해 캐시가 생긴 뒤 비행기 모드를 켭니다.
2. 위젯에 마지막 데이터가 남아 있는지 확인하고 **↻**를 누릅니다. 수동 갱신은 바로 연결을 시도하고, 실패 안내가 나타나도 캐시 화면은 계속 표시됩니다. 30분 정기 갱신은 네트워크 연결을 기다립니다.
3. 오프라인에서 할 일을 탭하면 낙관적으로 바뀌었다가 네트워크 오류 안내와 함께 원래 상태로 돌아와야 합니다. 비행기 모드를 끈 뒤 **↻**를 다시 눌러 동기화합니다.
4. daily 항목은 기기 현지 날짜가 바뀌면 `doneOn == 오늘` 규칙으로 미완료 상태가 됩니다. 자정 작업은 캐시 화면을 먼저 다시 그린 다음 네트워크 갱신을 요청합니다.

WorkManager는 Android 절전 상태에서 지연될 수 있습니다. 정기 갱신은 연결 상태에서 30분 주기로 요청하지만 정확한 30분 간격이나 자정 실행 시각을 보장하지 않습니다. 홈 화면에서 바로 최신 데이터를 확인하려면 **↻**를 사용하세요.

## 6. 확인 결과 전달

초기판 빌드는 `docs/android-verification.md`, 이전 개선판은 `docs/android-ux-verification.md`, 이전 APK 검수는 `docs/android-layout-colors-verification.md`, 이번 스크롤·색상 작업은 `docs/android-scroll-colors-verification.md`에 기록합니다. 연결 디버깅 기기 확인 결과와 S25에서 추가로 확인할 항목을 구분해 둡니다.

- 작은·중간·큰 위젯의 화면과 다크 모드 표시
- 위젯 체크 → 웹앱 반영, 웹앱 변경 → 위젯 새로고침 반영
- 비행기 모드에서 캐시 표시·오류 안내·체크 원복
- 날짜가 바뀐 뒤 daily 항목 표시
